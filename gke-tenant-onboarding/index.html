Shared GKE Platform · New Tenant Guide

Bring your service onto the platform

This walks a tenant team through everything between "we have an application" and "it's running in production on the shared GKE platform" — namespace request, access, your first deployment, ingress, CI/CD, observability, and the security guardrails every namespace runs under. Work through it top to bottom; each step assumes the one before it is done.

00

What you're onboarding to

One regional production cluster, shared across tenants by namespace. You own your workload; the platform team owns everything underneath it.

GOOD TO KNOW Every tenant gets one namespace per environment (dev, staging, prod), provisioned identically. Nothing below is a one-off — the same steps apply whether this is your first service or your tenth.
01

Prerequisites

Get access and tooling sorted before you touch the cluster.

Access

  • A Google identity in the org's Cloud Identity domain.
  • Membership in your team's access group — ask your manager to add you to gcp-tenant-<team>@company.com. Group membership is what drives your namespace RBAC, so this has to land before Step 3.
  • Access to the internal platform-tenants GitHub repo (used to request and configure your namespace).

Local tooling

macOS · install via Homebrew
$ brew install --cask google-cloud-sdk
$ brew install kubectl helm k9s
$ gcloud components install gke-gcloud-auth-plugin
verify everything is on PATH
$ gcloud version
$ kubectl version --client
$ helm version
$ gke-gcloud-auth-plugin --version

02

Request a namespace

Namespaces are provisioned by GitOps, not by ticket — you open a PR against a config file and automation does the rest.

Fork or branch platform-tenants and add a tenant file under tenants/<slug>.hcl:

tenants/payments.hcl
tenant "payments" {
  display_name  = "Payments Team"
  environments  = ["dev", "staging", "prod"]
  cost_center   = "CC-4821"
  slack_channel = "#payments-eng"
  repo          = "acme-org/payments-service"

  quota = {
    cpu    = "8"
    memory = "16Gi"
    pods   = "40"
  }
}

Open the PR against main. The platform team's bot validates the schema and quota request automatically; a human only reviews if you're asking for non-default quota.

What merging triggers

  • Namespaces created: tenant-payments-dev, tenant-payments-staging, tenant-payments-prod
  • RBAC bindings for your access group, scoped to those namespaces only
  • A ResourceQuota and default-deny NetworkPolicy applied to each
  • A Workload Identity binding for your future CI service account
  • A default Grafana dashboard and log-based view, pre-filtered to your namespace
TIMING Provisioning runs on merge and typically completes in 5–10 minutes. RBAC propagation to kubectl can lag a minute or two behind that — if Step 3 throws a permissions error immediately after merge, wait and retry before assuming something's wrong.
03

Authenticate & configure access

Point kubectl at the shared cluster and confirm your namespace-scoped permissions.

authenticate and fetch cluster credentials
$ gcloud auth login
$ gcloud config set project acme-platform-prod
$ gcloud container clusters get-credentials gke-shared-prod \
    --region us-central1 --project acme-platform-prod
confirm your context and permissions
$ kubectl config current-context
gke_acme-platform-prod_us-central1_gke-shared-prod

$ kubectl auth can-i create deployments -n tenant-payments-dev
yes

$ kubectl get namespace tenant-payments-dev
NAME                  STATUS   AGE
tenant-payments-dev   Active   4m

Two roles per namespace

RoleBound toCan do
tenant-adminyour access groupFull read/write in your namespaces, including secrets and RBAC review
tenant-deployCI service account (Workload Identity)Create/update workloads and config; cannot read secrets or modify RBAC
SCOPE Both roles are namespace-scoped. If kubectl ever reports a resource in another tenant's namespace, that's the RBAC working as intended, not a bug to route around.
04

Deploy your first workload

Same manifest shape works in every environment — only the namespace and replica count change.

Required on every workload: team and cost-center labels, and explicit CPU/memory requests and limits. The admission webhook rejects anything missing them before it's scheduled.

deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: payments-api
  namespace: tenant-payments-dev
  labels:
    app: payments-api
    team: payments
    cost-center: CC-4821
spec:
  replicas: 2
  selector:
    matchLabels: { app: payments-api }
  template:
    metadata:
      labels: { app: payments-api, team: payments }
    spec:
      containers:
        - name: payments-api
          image: us-central1-docker.pkg.dev/acme-platform-prod/payments/api:1.4.2
          ports: [{ containerPort: 8080 }]
          resources:
            requests: { cpu: "250m", memory: "256Mi" }
            limits:   { cpu: "500m", memory: "512Mi" }
          readinessProbe:
            httpGet: { path: /healthz, port: 8080 }
---
apiVersion: v1
kind: Service
metadata:
  name: payments-api
  namespace: tenant-payments-dev
spec:
  selector: { app: payments-api }
  ports: [{ port: 80, targetPort: 8080 }]
apply and watch it come up
$ kubectl apply -f deployment.yaml
$ kubectl get pods -n tenant-payments-dev -w
BEFORE PROD Production namespaces additionally require a PodDisruptionBudget and at least 2 replicas — the same manifest with minAvailable: 1 added covers it.
05

Expose the service

One shared Gateway handles TLS and DNS for every tenant — you declare a route, not a load balancer.

httproute.yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: payments-api
  namespace: tenant-payments-dev
spec:
  parentRefs:
    - name: shared-gateway
      namespace: platform-ingress
  hostnames: ["payments-api.dev.internal.acme.com"]
  rules:
    - backendRefs:
        - name: payments-api
          port: 80
  • TLS is issued automatically by cert-manager once the hostname resolves — no certificate to manage yourself.
  • DNS is created by external-dns watching the HTTPRoute; expect the CNAME within a few minutes of applying it.
  • Hostnames must live under your environment's reserved zone (*.dev.internal.acme.com, *.staging.internal.acme.com, *.acme.com for prod, subject to review).
06

Wire up CI/CD

Keyless deploys from GitHub Actions via Workload Identity Federation — no service account keys to store or rotate.

.github/workflows/deploy.yml
- uses: google-github-actions/auth@v2
  with:
    workload_identity_provider: projects/123456789/locations/global/workloadIdentityPools/tenant-pool/providers/github
    service_account: payments-deployer@acme-platform-prod.iam.gserviceaccount.com

- uses: google-github-actions/get-gke-credentials@v2
  with:
    cluster_name: gke-shared-prod
    location: us-central1

- run: kubectl set image deployment/payments-api \
    payments-api=us-central1-docker.pkg.dev/acme-platform-prod/payments/api:${{ github.sha }} \
    -n tenant-payments-dev

The payments-deployer service account was created for you in Step 2, bound to the tenant-deploy role in your namespaces only. Promotion between environments is the same workflow gated on branch or tag — e.g. merges to main deploy to staging, a release tag deploys to prod.

IMAGES Images must be pushed to your tenant's path in Artifact Registry (.../acme-platform-prod/payments/...). Production deploys additionally require a Binary Authorization attestation, produced automatically by the shared "build" workflow if you're using it.
07

Observability

Logs and a dashboard exist before you deploy anything; alerts are the one thing you have to add yourself.

Logs

Shipped to Cloud Logging automatically, pre-filtered by namespace. Saved view: logs.internal.acme.com/tenant-payments.

Metrics

Add prometheus.io/scrape: "true" and a /metrics port to your pod spec, or ship a PodMonitor alongside your manifests.

Dashboards

A default Grafana dashboard is provisioned per tenant at grafana.internal.acme.com/d/tenant-payments, seeded from your namespace's standard metrics.

Alerts

Not automatic. Ship a PrometheusRule in your repo; Alertmanager routes by the team label straight to the Slack channel you set in Step 2.

alerts.yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: payments-api-alerts
  namespace: tenant-payments-prod
  labels: { team: payments }
spec:
  groups:
    - name: payments-api
      rules:
        - alert: PaymentsApiHighErrorRate
          expr: sum(rate(http_requests_total{job="payments-api",code=~"5.."}[5m])) > 0.05
          for: 10m
          labels: { severity: warning, team: payments }
          annotations:
            summary: "payments-api 5xx rate above 5% for 10m"
08

Security & guardrails

These are enforced at the namespace level — the deployment fails closed rather than warns.

  • Pod Security Standards: restricted on every tenant namespace. No root, no privilege escalation, no host mounts. Set a non-root securityContext or the pod is rejected at admission.
  • Default-deny NetworkPolicy on ingress. Traffic between namespaces — including from another one of your own environments — needs an explicit NetworkPolicy allowing it.
  • Secrets never live in manifests. Store them in Secret Manager and mount via the CSI driver:
secretproviderclass.yaml
apiVersion: secrets-store.csi.x-k8s.io/v1
kind: SecretProviderClass
metadata:
  name: payments-api-secrets
  namespace: tenant-payments-prod
spec:
  provider: gcp
  parameters:
    secrets: |
      - resourceName: "projects/acme-platform-prod/secrets/payments-db-password/versions/latest"
        path: "db-password"
  • Images must come from your Artifact Registry path. Anything else is blocked by the admission policy.
  • Production images need a Binary Authorization attestation. The shared build workflow attaches this automatically — hand-pushed images won't have one and will be rejected in prod.
  • Quotas are real limits, not warnings. Once your namespace's CPU/memory/pod quota is hit, new pods stay Pending until something is freed or the quota is raised via the same PR flow as Step 2.

10

Troubleshooting

The failures nearly every tenant hits once, in the order they tend to show up.

SymptomLikely causeFix
Forbidden right after namespace creation RBAC hasn't propagated yet Wait 1–2 minutes and retry; escalate only if it persists past 15 minutes
Pod stuck Pending Namespace ResourceQuota exhausted kubectl describe resourcequota -n <ns>; free capacity or raise quota via a tenant-file PR
ImagePullBackOff Image outside your Artifact Registry path, or missing Workload Identity binding Confirm the image path and that the pulling service account has artifactregistry.reader
Pod rejected at admission Missing resource requests/limits, or a disallowed securityContext Add explicit requests/limits and a non-root security context
HTTPRoute returns 404 Hostname mismatch or route not yet reconciled Confirm the hostname matches exactly and check kubectl describe httproute for reconciliation errors
Prod deploy blocked Image missing a Binary Authorization attestation Rebuild through the shared build workflow rather than pushing the image directly
